Arquitectura - Hydra

Cómo se organiza la herramienta y cómo se relacionan sus componentes.

Hydra combina un núcleo que coordina la ejecución con módulos especializados en protocolos. El núcleo gestiona los parámetros, las entradas, las tareas concurrentes y la presentación de resultados; cada módulo implementa los detalles de comunicación con el servicio evaluado.

Es un esquema conceptual: los detalles internos pueden variar entre versiones y módulos. No todos los protocolos responden de la misma forma ni ofrecen la misma información.

Componentes

1. Interfaz de parámetros

Recibe el host, el servicio, los usuarios, las contraseñas, el puerto y las opciones generales o específicas del módulo. La sintaxis debe validarse con la ayuda de la versión instalada.

2. Gestor de entradas

Lee valores individuales o archivos de entrada y organiza las combinaciones que se comprobarán. El tamaño de las listas determina el volumen potencial de trabajo.

3. Motor de concurrencia

Distribuye las tareas entre conexiones simultáneas. Los límites de concurrencia, espera y timeout influyen en la velocidad, la estabilidad y la posibilidad de activar controles defensivos.

4. Módulos de protocolo

Implementan el diálogo específico de cada servicio. Por eso las opciones de un módulo HTTP no tienen por qué ser válidas para SSH, FTP, SMTP u otros servicios.

La disponibilidad real depende de la versión y de las bibliotecas presentes durante la compilación. Consulta hydra -h y hydra -U nombre_modulo.

5. Clasificación y salida

El módulo interpreta las respuestas y el núcleo presenta los resultados. Una conexión fallida, una respuesta ambigua o un bloqueo no deben confundirse con una contraseña incorrecta.

Parámetros que afectan al comportamiento

  • -t: número de tareas paralelas por objetivo, según el modo de ejecución.
  • -w: tiempo máximo de espera por respuesta.
  • -W: espera entre conexiones que realiza una tarea.
  • -s: puerto del servicio cuando no se utiliza el predeterminado.
  • -o: guarda la salida en un archivo.
  • -v / -V: aumentan el detalle de salida; revisa la ayuda de tu versión.

Protocolos y módulos

La documentación de Hydra incluye módulos para servicios como SSH, FTP, HTTP(S), SMTP, IMAP, POP3, SMB, LDAP, bases de datos y otros. Esta lista no debe interpretarse como garantía de que todos estén habilitados en cualquier instalación.

Qué no hace el motor

  • No determina por sí solo si una aplicación tiene una vulnerabilidad de software.
  • No sustituye la revisión de políticas de contraseñas ni la comprobación manual.
  • No puede inferir con certeza el estado de una cuenta si el servicio oculta o uniformiza respuestas.
