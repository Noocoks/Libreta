Hydra

Auditoría automatizada de autenticación en servicios de red.

pentesting credenciales protocolos SSH FTP

THC Hydra es una herramienta de código abierto para evaluar mecanismos de autenticación en servicios de red. Automatiza la comprobación de pares usuario/contraseña mediante módulos específicos para cada protocolo y permite distribuir las pruebas entre varias tareas concurrentes.

Su función es probar credenciales frente a un servicio; no explota por sí misma una vulnerabilidad del sistema ni garantiza que un resultado sea válido si el protocolo, el formulario o la respuesta del servidor se han interpretado incorrectamente.


Qué problema permite estudiar

Hydra ayuda a comprobar si las credenciales de cuentas de prueba son previsibles y si el servicio aplica controles adecuados ante intentos repetidos. En una auditoría bien delimitada también permite observar registros, alertas, retardos y bloqueos.


Conceptos fundamentales

Objetivo y servicio

El objetivo identifica el host autorizado. El servicio o módulo determina el protocolo y la lógica de autenticación que se utilizará, por ejemplo SSH, FTP o un formulario HTTP.

Credenciales de entrada

Se pueden proporcionar valores individuales o archivos con usuarios y contraseñas. Las opciones de entrada determinan cómo se combinan. Una lista grande puede producir muchas solicitudes y no debe utilizarse sin calcular antes el alcance.

Concurrencia

Hydra permite ejecutar varias tareas simultáneas. Aumentar la concurrencia no siempre mejora el resultado: puede saturar el servicio, provocar bloqueos, activar defensas o producir falsos errores por límites de conexión.

Módulos

Cada módulo adapta la comunicación al servicio. Sus opciones no son necesariamente intercambiables: consulta la ayuda del módulo concreto antes de interpretar sus parámetros.


Casos de uso legítimos

  1. Auditoría de contraseñas: evaluar cuentas de laboratorio o cuentas de prueba aprobadas.
  2. Validación defensiva: observar si el servicio limita intentos y genera registros útiles.
  3. Formación: estudiar la relación entre contraseñas débiles, autenticación y monitorización.

Instalación y comprobación

En distribuciones basadas en Debian, Ubuntu o Kali:

sudo apt update
sudo apt install hydra

command -v hydra
hydra -h
hydra -U ssh

hydra -h muestra la ayuda general. hydra -U ssh consulta las opciones específicas del módulo SSH disponible en esa compilación. La lista de módulos puede variar según las bibliotecas instaladas al compilar el programa.


Cómo interpretar los resultados

  • Autenticación aceptada: el módulo considera que el servicio ha aceptado las credenciales; valida el resultado con los registros del servidor.
  • Credenciales rechazadas: la respuesta se interpreta como un fallo de autenticación.
  • Error de conexión: puede deberse a red, firewall, servicio detenido, timeout o límites del servidor.
  • Bloqueo o limitación: la prueba puede haber activado controles defensivos; detén la ejecución y revisa los registros.

Limitaciones y errores habituales

  • Un módulo incorrecto o mal configurado puede interpretar mal las respuestas.
  • Los formularios web pueden cambiar sus campos, tokens, cookies o mecanismos anti-CSRF.
  • Los límites de conexión y los bloqueos alteran los resultados.
  • Un puerto accesible no implica que la autenticación sea vulnerable.
  • El volumen de intentos puede afectar a la disponibilidad del servicio.

Medidas defensivas relacionadas

  • Contraseñas largas, únicas y almacenadas mediante algoritmos adecuados.
  • Autenticación multifactor, preferiblemente resistente al phishing.
  • Limitación de intentos, retardos progresivos y detección de patrones distribuidos.
  • Alertas ante fallos repetidos y revisión centralizada de registros.
  • Deshabilitar servicios de administración innecesarios y restringir su acceso por red.

Regla de laboratorio: utiliza únicamente sistemas propios o autorizados, cuentas desechables y objetivos locales. Define un límite de solicitudes, una ventana de ejecución y un procedimiento para detener la prueba.
