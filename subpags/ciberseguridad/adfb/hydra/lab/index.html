Laboratorio - Hydra

laboratorio localhost SSH logs

El objetivo es observar cómo se comporta SSH ante una pequeña prueba de autenticación automatizada y relacionar los resultados con los registros del sistema. Todos los comandos de esta práctica apuntan a 127.0.0.1, es decir, al propio equipo.

No cambies el objetivo por una IP pública, un equipo de la red o una cuenta real. Usa una máquina virtual desechable o un entorno local que controles.


1. Preparar el entorno

En Debian, Ubuntu o Kali instala el servicio SSH y Hydra:

sudo apt update
sudo apt install openssh-server hydra
sudo systemctl enable --now ssh
systemctl status ssh --no-pager

Comprueba que SSH escucha localmente:

ss -lnt | grep ':22'

2. Crear una cuenta de laboratorio

Crea una cuenta temporal que no tenga permisos administrativos. Establece una contraseña de práctica que no utilices en ningún otro servicio: 

sudo adduser labuser
sudo passwd labuser

La contraseña se introduce de forma interactiva. No reutilices una contraseña personal ni incluyas información real en los archivos de prueba.


3. Crear una lista pequeña

Prepara una lista corta que contenga la contraseña de laboratorio y algunos valores ficticios. La lista debe ser pequeña para que el ejercicio sea predecible y no genere carga innecesaria. 

printf '%s\n' 'ClaveLab-Temporal-01' 'valor-ficticio-02' 'valor-ficticio-03' > claves-lab.txt
chmod 600 claves-lab.txt

Asegúrate de haber establecido exactamente la primera entrada como contraseña de labuser durante el paso anterior. Si elegiste otra, edita la lista para que coincida.


4. Ejecutar una comprobación limitada

hydra -l labuser -P claves-lab.txt ssh://127.0.0.1 -t 1 -W 2
  • -l indica el usuario de prueba.
  • -P indica el archivo de contraseñas.
  • ssh://127.0.0.1 limita el destino al propio equipo.
  • -t 1 utiliza una sola tarea concurrente.
  • -W 2 introduce una espera entre conexiones de la tarea.

5. Observar los registros

En otra terminal, consulta los registros de autenticación:

sudo journalctl -u ssh --since "10 minutes ago"
sudo tail -n 50 /var/log/auth.log

La ruta /var/log/auth.log depende de la distribución y de su configuración de logging. Si no existe, utiliza el journal de systemd.


6. Analizar los resultados

  • Compara el número de intentos de la herramienta con los eventos registrados.
  • Comprueba qué usuario aparece en los eventos y las marcas temporales.
  • Distingue un rechazo de autenticación de un error de conexión.
  • Verifica manualmente que la cuenta de laboratorio sigue funcionando.

7. Restaurar el laboratorio

sudo passwd -l labuser
sudo deluser --remove-home labuser
rm -f claves-lab.txt

Si necesitas repetir la práctica, crea de nuevo la cuenta temporal. También puedes restaurar una instantánea de la máquina virtual.


Conclusión y medidas defensivas

  • Utiliza contraseñas largas y únicas.
  • Deshabilita el acceso SSH por contraseña cuando sea viable y utiliza claves protegidas.
  • Restringe SSH por firewall y red de administración.
  • Aplica MFA cuando la arquitectura lo permita.
  • Centraliza registros y configura alertas de intentos anómalos.

Nota: esta práctica demuestra un mecanismo de autenticación, no la seguridad global del servidor. Un resultado de Hydra debe contrastarse siempre con los registros del servicio.
