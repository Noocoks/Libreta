Arquitectura - Medusa

Medusa separa el programa principal de los módulos de protocolo. El núcleo coordina las entradas y la ejecución; los módulos implementan la comunicación con cada servicio. Este diseño permite ampliar la compatibilidad sin reescribir el motor principal.

Componentes principales

Núcleo

Interpreta opciones, prepara el trabajo y coordina los módulos.

Gestor de entradas

Gestiona objetivos, usuarios y contraseñas. Estos datos pueden proceder de valores individuales o de archivos. El formato y la combinación de entradas deben revisarse antes de ejecutar una prueba.

Gestor de hilos

Distribuye tareas concurrentes. La concurrencia efectiva está condicionada por los parámetros, el módulo, la red y los límites del servicio remoto.

Módulos independientes

Los módulos se distribuyen como componentes separados y contienen la lógica específica del protocolo. Algunos requieren bibliotecas de desarrollo adicionales para compilarse.

Gestión de resultados

Recoge respuestas, errores y estados de autenticación. Una respuesta ambigua o un timeout debe registrarse como incertidumbre, no como una credencial necesariamente incorrecta.

Comprobar los módulos disponibles

medusa -d
medusa -M ssh -q

El primer comando enumera los módulos instalados. El segundo consulta las opciones del módulo SSH. Si no aparece, comprueba el paquete y sus dependencias antes de asumir que el protocolo está soportado.

Dependencias y compilación

La documentación de Medusa indica que ciertos módulos dependen de bibliotecas externas, como OpenSSL, LibSSH2 o bibliotecas específicas de bases de datos y servicios. Por ello, dos instalaciones con versiones similares pueden ofrecer conjuntos de módulos distintos.
