Medusa

Auditor de autenticación de red modular y multihilo.

SSH FTP autenticación módulos auditoría

Medusa es una herramienta de código abierto diseñada para realizar auditorías automatizadas de inicio de sesión en servicios de red. Su arquitectura utiliza hilos de ejecución y módulos independientes para los distintos protocolos de autenticación.

Se utiliza para evaluar credenciales y controles de acceso en sistemas propios o autorizados. No es un escáner general de vulnerabilidades: su ámbito principal es la autenticación remota.


Cómo funciona

  1. Se define el host o conjunto de hosts que forman parte del alcance.
  2. Se selecciona un módulo compatible con el servicio.
  3. Se proporcionan usuarios y contraseñas individuales o mediante archivos.
  4. El programa distribuye el trabajo entre hilos, de acuerdo con los límites configurados.
  5. El módulo realiza el intercambio de autenticación y clasifica la respuesta.
  6. Los resultados y errores se muestran para su análisis.

Conceptos importantes

Módulos

Cada servicio dispone de un módulo específico. La instalación puede incluir un conjunto diferente según las dependencias disponibles durante la compilación.

Paralelización

Medusa puede probar distintos hosts, usuarios o contraseñas de forma concurrente. Más hilos no significan necesariamente mejores resultados: el servicio puede limitar conexiones o bloquear cuentas.

Opciones del módulo

Algunos protocolos necesitan parámetros adicionales, por ejemplo dominio, modo de autenticación o comportamiento específico del servicio. Consulta la ayuda del módulo antes de usarlo.


Servicios y protocolos

La documentación del proyecto enumera módulos para servicios como SSH, FTP, HTTP, SMB, SMTP, POP3, IMAP, RDP, VNC, bases de datos y otros. La disponibilidad concreta debe comprobarse en la instalación local.


Instalación y verificación

sudo apt update
sudo apt install medusa

command -v medusa
medusa -V
medusa -h
medusa -d

medusa -d muestra los módulos instalados. Para consultar las opciones de un módulo concreto, utiliza medusa -M ssh -q si el módulo SSH está disponible.


Interpretación de resultados

  • Una autenticación aceptada debe contrastarse con los registros del servicio.
  • Un error de conexión no demuestra que la contraseña sea incorrecta.
  • Un módulo ausente suele indicar que no se compiló o instaló la dependencia necesaria.
  • Los límites de intentos, bloqueos y respuestas genéricas pueden dificultar la clasificación.

Medusa y Hydra

Ambas herramientas persiguen objetivos similares y tienen una arquitectura modular y concurrente. La elección depende de los módulos disponibles, la compatibilidad con el servicio, la facilidad de uso, la documentación y las necesidades concretas de la auditoría. No existe una ganadora universal por velocidad o número de protocolos.


Buenas prácticas y defensa

  • Define por escrito el alcance y utiliza cuentas de prueba.
  • Limita la concurrencia y la duración de las pruebas.
  • Aplica MFA, contraseñas únicas y controles contra intentos repetidos.
  • Supervisa eventos de autenticación y correlaciónalos entre servicios.
  • Detén la prueba si aparecen bloqueos inesperados o degradación.
