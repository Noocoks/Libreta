Laboratorio - Medusa

Esta práctica utiliza SSH en 127.0.0.1 para estudiar el comportamiento de Medusa y los registros del sistema. No la ejecutes contra equipos de terceros ni contra cuentas reales.


1. Preparar el servicio local

sudo apt update
sudo apt install openssh-server medusa
sudo systemctl enable --now ssh
systemctl status ssh --no-pager
ss -lnt | grep ':22'

2. Crear una cuenta temporal

sudo adduser medusa-lab
sudo passwd medusa-lab

Establece una contraseña de laboratorio que no reutilices. No asignes permisos administrativos a esta cuenta.


3. Crear una lista corta de práctica

printf '%s\n' 'ClaveMedusa-Lab-01' 'valor-ficticio-02' 'valor-ficticio-03' > claves-medusa.txt
chmod 600 claves-medusa.txt

Asegúrate de que la contraseña establecida para la cuenta coincide con la primera entrada.


4. Verificar los módulos

medusa -d
medusa -M ssh -q

Continúa solo si el módulo SSH está instalado. La ayuda del módulo permite conocer sus opciones particulares.


5. Prueba limitada sobre localhost

medusa -h 127.0.0.1 -u medusa-lab -P claves-medusa.txt -M ssh -t 1

El destino es el propio equipo y se utiliza un único hilo. Mantén la lista reducida y detén el ejercicio si el servicio muestra errores o bloqueos inesperados.


6. Revisar registros

sudo journalctl -u ssh --since "10 minutes ago"
sudo tail -n 50 /var/log/auth.log

La disponibilidad de /var/log/auth.log depende de la distribución. El journal de systemd es una alternativa cuando el servicio registra allí sus eventos.


7. Informe de práctica

  • Versión de Medusa y módulos disponibles.
  • Servicio y dirección local evaluados.
  • Número de intentos y duración.
  • Eventos de autenticación observados en los registros.
  • Diferencias entre errores de conexión y rechazos de credenciales.
  • Medidas defensivas recomendadas.

8. Limpieza

sudo passwd -l medusa-lab
sudo deluser --remove-home medusa-lab
rm -f claves-medusa.txt

Si trabajas en una máquina virtual, restaura la instantánea al terminar.
