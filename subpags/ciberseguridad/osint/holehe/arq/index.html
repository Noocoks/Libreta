Arquitectura - Holehe

Holehe organiza comprobaciones mediante módulos asociados a servicios concretos. Cada módulo implementa una consulta y conoce las señales que intenta interpretar. El resultado depende de que el proveedor mantenga el comportamiento esperado.

Componentes

Entrada

Recibe la dirección que se comprobará. Debe ser propia o estar cubierta por autorización expresa.

Módulos de servicio

Cada módulo implementa una consulta particular. No todos los proveedores usan los mismos endpoints, mensajes ni respuestas.

Cliente HTTP y concurrencia

Coordina solicitudes y respuestas. Las consultas deben respetar los límites y controles antiabuso de los servicios.

Analizador

Examina códigos, texto y señales indirectas. Un cambio en la web del proveedor puede invalidar la lógica de un módulo.

Clasificador

Resume los resultados y debe conservar estados de limitación e incertidumbre; reducirlos a un sí/no puede inducir a error.

Estados de salida

  • Found: señal compatible con una cuenta existente.
  • Not found: no se detectó una señal de registro.
  • Rate limited: el proveedor limitó la frecuencia de consultas.
  • Uncertain / error: no existe evidencia suficiente.

Riesgo de enumeración

La enumeración puede revelar en qué plataformas se utiliza una dirección. Los proveedores reducen este riesgo con respuestas uniformes, límites de frecuencia y controles antiautomatización.
