MailHog

MailHog es una herramienta para probar el envío de correo. Proporciona un servidor SMTP que recibe mensajes de aplicaciones y una interfaz web para inspeccionarlos sin entregarlos a destinatarios reales.

Es útil para revisar cabeceras, contenido HTML y adjuntos antes de configurar un servidor de correo de producción.


Funcionamiento

  1. La aplicación envía el mensaje al host y puerto SMTP de MailHog.
  2. MailHog recibe y almacena el mensaje según su configuración.
  3. La interfaz web permite inspeccionar el mensaje.
  4. La API HTTP permite automatizar comprobaciones en pruebas.

Puertos habituales

  • 1025/TCP: servidor SMTP.
  • 8025/TCP: interfaz web y API.

Son los valores predeterminados habituales, pero pueden cambiarse. En un laboratorio limita la publicación a loopback para que otros equipos no accedan al servicio.

Qué puedes comprobar

  • Asunto, remitente y destinatarios.
  • Cabeceras y estructura MIME.
  • Contenido de texto y HTML.
  • Adjuntos y codificación.
  • Que la aplicación utiliza el host y puerto previstos.

Almacenamiento y límites

El almacenamiento predeterminado es volátil y los mensajes pueden perderse al reiniciar o recrear el proceso. El proyecto documenta opciones de persistencia que deben configurarse expresamente.

MailHog es un servidor de pruebas, no un relay de producción. No lo expongas como servicio abierto ni lo utilices para entregar correo real.

Integración con GoPhish

Si ambos procesos se ejecutan en el mismo host, configura SMTP como 127.0.0.1:1025. Si están en contenedores distintos, utiliza la red interna de Docker y el nombre del servicio: la dirección loopback de un contenedor apunta a ese mismo contenedor.

Estado y mantenimiento

El repositorio upstream de MailHog es un proyecto antiguo. Antes de integrarlo en un entorno actual, comprueba mantenimiento, compatibilidad y seguridad de la imagen utilizada. Para prácticas, mantenlo aislado.
