Inicialización - MailHog

Esta guía publica los puertos de MailHog únicamente en localhost. Así, la interfaz web y el SMTP de pruebas no quedan accesibles desde otros equipos de la red.


1. Comprobar Docker

docker --version
sudo systemctl status docker --no-pager

2. Crear el contenedor

docker run -d \
    --name mailhog \
    --restart unless-stopped \
    -p 127.0.0.1:1025:1025 \
    -p 127.0.0.1:8025:8025 \
    mailhog/mailhog

El prefijo 127.0.0.1 limita los puertos publicados al propio equipo. No lo elimines en un laboratorio que no deba ser accesible desde la red.


3. Verificar

docker ps --filter name=mailhog
docker logs --tail 50 mailhog
curl -I http://127.0.0.1:8025

Abre http://127.0.0.1:8025. La interfaz debe mostrar la bandeja de mensajes.


4. Configurar la aplicación

  • Host SMTP: 127.0.0.1
  • Puerto: 1025
  • TLS: desactivado en la configuración local predeterminada.
  • Autenticación: no configurada de forma predeterminada.

Estos parámetros son exclusivos de pruebas locales; no los utilices para correo real ni para aplicaciones expuestas.


5. Gestión

docker stop mailhog
docker start mailhog
docker restart mailhog
docker logs -f mailhog

6. Eliminar el laboratorio

docker stop mailhog
docker rm mailhog

Si también quieres eliminar la imagen local, comprueba antes que ningún otro contenedor la utiliza y ejecuta docker image rm mailhog/mailhog.


Solución de problemas

  • Puerto ocupado: revisa ss -lntp.
  • Interfaz inaccesible: revisa estado y logs del contenedor.
  • Sin mensajes: comprueba host, puerto y conectividad entre servicios.
  • Mensajes perdidos: el almacenamiento predeterminado puede ser volátil.

Seguridad: MailHog no debe funcionar como relay de producción. Mantén los puertos limitados a localhost y evita opciones de liberación de mensajes hacia servidores reales.
