Proyecto de IA local

python openai anthropic api venv

Este apartado documenta la preparación de un entorno de trabajo local para utilizar distintos proveedores de inteligencia artificial desde Python. Los modelos se ejecutan en la infraestructura del proveedor: el equipo local ejecuta los scripts y se comunica con ellos mediante sus APIs.

La separación por entornos virtuales, variables de entorno y módulos facilita probar cada proveedor y desarrollar herramientas que puedan alternar entre varios modelos.


Estructura del proyecto

~/ai/
├── venv/
├── .env
├── .gitignore
├── test_openai.py
├── test_claude.py
└── otros_scripts.py

venv/ contiene las dependencias aisladas del proyecto. .env almacena las claves API, mientras que .gitignore evita que los secretos y el entorno virtual se incorporen al repositorio.


Creación del entorno virtual

mkdir ~/ai
cd ~/ai
python3 -m venv venv
source venv/bin/activate

El entorno virtual mantiene las bibliotecas de este proyecto separadas de las instaladas globalmente en el sistema. Cuando esté activo, normalmente aparecerá el nombre venv en el prompt.


Acceso rápido

cd ~/ai
source venv/bin/activate

Ejecuta estos comandos cada vez que abras una terminal nueva y quieras trabajar en el proyecto. Para salir del entorno utiliza deactivate.


Instalación de dependencias

python -m pip install --upgrade pip
pip install openai anthropic python-dotenv

openai y anthropic son los SDK oficiales de cada proveedor. python-dotenv permite cargar variables desde un archivo .env. Instala únicamente las bibliotecas que utilice cada script; herramientas como Shell-GPT o IPython son complementarias, no requisitos para llamar a las APIs.


Herramientas complementarias

En la configuración original también se contemplaban Shell-GPT e IPython. No son necesarios para utilizar directamente los SDK de OpenAI y Anthropic, pero pueden añadirse para trabajar desde la terminal y disponer de una consola interactiva: 

pip install shell-gpt ipython

Consulta las páginas específicas de cada herramienta antes de utilizarlas; Shell-GPT puede gestionar su propia configuración y credenciales, independiente del archivo .env de estos scripts.


Gestión segura de las claves API

Una clave API autentica las peticiones realizadas a un proveedor. Debe tratarse como una contraseña: no la incluyas directamente en el código, capturas públicas, mensajes de error ni repositorios. 

nano .env

Ejemplo de estructura del archivo:

OPENAI_API_KEY=tu_clave_de_openai
ANTHROPIC_API_KEY=tu_clave_de_anthropic

Sustituye los valores de ejemplo por las claves generadas en los paneles oficiales. No compartas el archivo ni publiques sus valores. 

chmod 600 .env

En sistemas Unix, este permiso limita la lectura y escritura del archivo a su propietario. Añade también estas entradas a .gitignore: 

.env
venv/
__pycache__/

Importante: el acceso a ChatGPT o Claude mediante sus aplicaciones web no implica que las llamadas API estén incluidas en la misma suscripción. Consulta la facturación y los límites de cada plataforma antes de ejecutar pruebas repetidas.


Cómo funciona una petición

  1. El script carga las variables del entorno.
  2. El SDK construye una petición HTTP autenticada.
  3. El proveedor procesa la entrada con el modelo seleccionado.
  4. La API devuelve una respuesta que el script interpreta.
  5. El programa muestra o almacena el resultado según su diseño.

La conexión requiere Internet y una clave válida. El código se ejecuta localmente, pero la inferencia de estos proveedores no se realiza en tu ordenador.


Flujo de trabajo

  1. Crear la carpeta y el entorno virtual.
  2. Instalar los SDK y las dependencias necesarias.
  3. Generar las claves API y guardarlas en .env.
  4. Proteger los secretos con permisos y reglas de Git.
  5. Ejecutar por separado las pruebas de OpenAI y Anthropic.
  6. Comprobar errores de autenticación, conexión y límites.
  7. Integrar los proveedores en scripts propios cuando las pruebas funcionen.
