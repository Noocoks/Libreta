Redes, transferencia y acceso remoto

LocalSend

Aplicación multiplataforma para transferir archivos y texto directamente entre dispositivos de una misma red local, sin cuenta ni servidor externo obligatorio.

Público objetivo: Usuarios que comparten archivos entre PC, móviles y tablets en una LAN.

Plataformas: Windows, macOS, GNU/Linux, Android e iOS.

Qué es y cómo funciona

LocalSend utiliza un protocolo REST sobre HTTP para las operaciones de descubrimiento y transferencia. El descubrimiento predeterminado usa multicast UDP en el grupo 224.0.0.167; la transferencia utiliza un servidor HTTP local sobre TCP. El protocolo v1 incluye un campo fingerprint aleatorio para evitar que un dispositivo se descubra a sí mismo; no es una autenticación criptográfica del dispositivo. La especificación describe HTTP sobre TCP para descubrimiento y transferencia. No requiere un servicio central de almacenamiento.

Funciones principales

Descubrimiento de dispositivos en la LAN, envío y recepción de archivos, carpetas y texto, aceptación o rechazo de transferencias, alias de dispositivo, configuración de puertos y modos alternativos de descubrimiento.

Instalación y configuración

Instala la aplicación oficial en ambos dispositivos y conéctalos a una red donde puedan comunicarse. Permite LocalSend en el firewall privado. El protocolo usa por defecto UDP 53317 para multicast y TCP 53317 para el servidor HTTP; ambos valores se pueden cambiar desde la configuración si están ocupados o bloqueados. No abras estos puertos en el router hacia Internet para un uso local normal.

Compatibilidad y estado

Windows, macOS, GNU/Linux, Android e iOS.

Verificación editorial 28-11-2026. La especificación oficial consultada define los puertos UDP/TCP predeterminados y permite configurarlos desde la aplicación.

Licencia y distribución

Software libre y de código abierto; gratuito.

Seguridad, privacidad y limitaciones

El protocolo v1 documenta HTTP/TCP y no describe cifrado de extremo a extremo. No presupongas que el contenido está cifrado en tránsito ni que el campo fingerprint autentica al remitente. Acepta solo solicitudes esperadas, evita redes públicas o compartidas y limita el firewall a redes privadas controladas. La aplicación no necesita exponer el puerto en Internet.
